## Convenciones v3 (Prompt guia.md v3)
- Autoría: `metadata.author = "DeveloClick"` (exacto; `getAuthor` acepta id o nombre). `estandarGuia: 3` y `activoOriginal` en metadata. `authorBio` solo si el autor la da.
- Evidencia: `evidence: {}` (o no referenciarlo). Solo el autor rellena `pruebas` (`promptId`, `fecha`, `asistente`, `nota`), `casoReal`, `revisadoEn`. Sin prueba, el prompt se presenta como «diseñado para».
- Constantes: lo que aparece en varios sitios (campos, criterios, umbrales, datos del caso) se define una vez arriba de `data.ts` y se lee de ahí (los prompts pueden interpolarlo con `${…}`). Sin `hero.tools`; los pasos de `method` son la checklist (`<StepSection checkable guide={data.metadata.slug}/>`); `application` = qué hacer DESPUÉS.
- Índice: `<GuideSection … part="…">` con 6–8 partes (`GuideToc` lista partes). Cada prompt una sola vez con `<PromptCard prompt={data.prompts.x} proof={data.images.pruebaN} evidence={data.evidence}/>` (constructor, texto plegable, copiar); iteración sin repetir el prompt: `<IterationBlock data={data.iteration}/>`. Fichas sin «datos previos» ni «ejemplo de uso» (`evaluate`, `improve`, `conversation` en entrevistas).
- Manifiesto: cada prompt tiene `prueba-prompt-0N.webp` con `promptId: "<clave>"`; todo slot con `description` (2–4 frases), `alt`, `ratio`.
- Prompts (10 puntos): rol/objetivo/destinatario; bloques `### CONTEXTO/DATOS/REGLAS/FORMATO DE SALIDA`; trazabilidad; `[FALTA: …]`; formato exacto; «antes de responder, verifica que…»; límites y reglas de borde; encadenado; sin relleno; agnóstico. Para que `parsePrompts` del `.mjs` los lea: `    clave: {` y `title:` en la línea siguiente; `prompt:` con plantilla literal sin backticks internos y sin líneas que empiecen con 2 espacios + `palabra:`.
- Contrato del `.mjs`: exige `hero.webp`, `prueba-prompt-0N.webp` por prompt, `description/alt/ratio` en todos los slots, `data.x` definido con clave de 2 espacios (`  x:`), cada prompt usado y mostrado una vez, sin «AdSense», autor exacto, `README` con «verificado» si `handlesNumbers`. `antes-despues` (beforeAfter) es opcional: solo si aporta algo que el análisis no dice. Avisa >5000 palabras (texto explicativo objetivo 3.000–4.500; el `.mjs` cuenta también tablas y fichas).
- Tiempo de lectura mostrado = `lib/guides/registry.ts` (≈200 pal/min sobre todo el texto visible salvo el texto de los prompts, que se copia y no se lee); incluye ejemplos y tablas, así que sale mayor que el texto explicativo (3.000–4.500).
- Ejemplos generados = aplicar literalmente el prompt; defectos del primer resultado solo los que el prompt no puede impedir; toda atribución «el prompt pide…» debe existir en una línea.
